# 🧪 Task Manager — API & UI Test Automation

**Статус проекта: в разработке**

Многомодульный Maven-проект автоматизации тестирования веб-приложения **Task Manager**, разработанного на Java и Spring Boot.

Проект создаётся в рамках выпускной квалификационной работы и демонстрирует организацию автоматизированного тестирования на уровнях API, UI и базы данных.

**Тестируемое приложение:** [Task Manager](https://github.com/MukhtarPashaTarkovskiy/task-manager)

**Тестовая среда:** [Task Manager — TEST](https://task-manager-test-588r.onrender.com)

## 🛠 Технологический стек

- **Java 17** — язык программирования
- **Maven** — многомодульная сборка
- **REST Assured** — автоматизация API-тестирования
- **TestNG** — тестовые сценарии, проверки и параметризация
- **Selenium / Selenide** — автоматизация UI-тестирования
- **PostgreSQL / JDBC** — проверка данных в тестовой БД
- **Jackson** — работа с JSON
- **Allure TestNG** — интеграция с системой отчётности
- **Git / GitHub** — контроль версий

```text
task-manager-autotests/
```

Модули разделяют API- и UI-тестирование, но относятся к одному тестируемому приложению.

## ✅ API-тестирование — `api-tests`

Реализованы автоматизированные проверки REST API с использованием REST Assured и TestNG.

### Регистрация пользователей

- Позитивные сценарии регистрации
- Проверка HTTP-статусов и тела ответа
- Негативные сценарии с некорректными входными данными
- Проверка сообщений валидации
- Параметризация тестовых данных
- Проверка сохранения пользователя в PostgreSQL

### Авторизация и безопасность

В тестовом проекте предусмотрена работа с механизмами авторизации приложения:

- HTTP-сессии
- CSRF-токены
- Передача необходимых заголовков и cookies
- Проверки поведения API при различных входных данных

### Проверки базы данных

Для взаимодействия с тестовой PostgreSQL используется JDBC.

- Получение соединения через переменные окружения
- Проверка подключения к нужной тестовой базе
- SQL-проверки созданных тестовых данных
- Удаление данных, созданных автотестами

### Управление тестовыми данными

Тестовые пользователи создаются с уникальными идентификаторами.

После выполнения проверок предусмотрена очистка созданных записей, в том числе при неуспешном выполнении теста.

Удаление ограничено специально созданными тестовыми данными, чтобы не затронуть других пользователей.

## 🖥 UI-тестирование — `ui-tests`

**Модуль находится в разработке.**

Реализуется автоматизация пользовательских сценариев через браузер с использованием Selenium/Selenide и TestNG.

Используется подход **Page Object Model** для разделения тестовой логики и взаимодействия с элементами страниц.

Ведётся разработка проверок авторизации, ожиданий загрузки приложения и перехода на страницу задач.

## 🌐 Тестовое окружение

Для тестирования используется отдельная среда приложения:

- **TEST:** https://task-manager-test-588r.onrender.com
- **PROD:** https://task-manager-kqoi.onrender.com

Тестовая среда подключена к отдельной PostgreSQL-базе в Neon.

Это позволяет выполнять проверки и управлять тестовыми данными без обращения к продуктивной базе.

При первом обращении Render может потребоваться дополнительное время на запуск приложения.

## 🔐 Конфигурация и безопасность

Данные для подключения к тестовой БД и тестовые пароли передаются через переменные окружения:

```text
TEST_USER_PASSWORD
TEST_DB_URL
TEST_DB_USERNAME
TEST_DB_PASSWORD
```

Секреты не должны храниться в исходном коде или попадать в Git.

## 🚀 Запуск тестов

Требования: **JDK 17**, **Maven**, доступ к тестовому окружению и необходимые переменные окружения.

```bash
git clone https://github.com/MukhtarPashaTarkovskiy/task-manager-autotests.git
cd task-manager-autotests
```

Запуск API-модуля:

```bash
mvn -pl api-tests test
```

Запуск всех модулей после завершения их настройки:

```bash
mvn clean test
```
