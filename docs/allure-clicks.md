# Allure двумя кнопками IntelliJ

Один раз выполнить **Reload All Maven Projects** (обновлены POM модулей). `All Tests` и VM options TestNG менять не нужно.

После тестирования:

1. У корневого `task-manager-autotests` раскрыть **Maven → Plugins → allure**.
2. Дважды нажать **allure:serve** — открыть последний полноценный общий отчёт API + UI в браузере. Сервер остаётся запущенным; остановить красной кнопкой IntelliJ.
3. **allure:report** — сформировать HTML того же запуска без выполнения тестов. Путь к HTML выводится в Maven-консоли.

Для отдельных результатов нажимать те же цели у **api-tests** или **ui-tests**. Корневой отчёт не заменяется одним модулем или незавершённым запуском. Зелёная кнопка All Tests по-прежнему выполняет `test -fae`; пути и Run ID вводить не требуется.

## Как это устроено

Существующий ReportingListener после записи completed.marker вызывает LatestAllurePublisher. Это работает и в Surefire, и в прямом IntelliJ TestNG. Бизнес-тесты, suites и конфигурации запуска не изменены.

Publisher проверяет Run ID, module/suite identity, наличие маркеров, результатов и вложений. Общий указатель публикуется только при завершении обоих модулей одного All-запуска и наличии всех методов бизнес-тестов по текущим исходникам. Произвольный выборочный прогон обоих модулей не подменяет полный общий отчёт. Ошибки, broken и skipped не делают завершённый запуск невалидным: их фактические результаты должны быть видны.

Для каждого run/scope создаётся ровно один `prepared/<scope>-<kind>`:

- `input` — рабочая копия результатов и seed history для Maven Plugin;
- `html` — канонический HTML и история, сформированные однократно;
- `view` — ограниченный рабочий output стандартного allure:report;
- `publication.json` — Run ID, состав, статистика и хеш исходных данных.

Сначала всё строится во временном `.pending-*`, проверяются реальные Allure summary counts. Затем каталог публикуется атомарным move. Только после этого одним atomic replace обновляется `.mvn/maven.config`: это локальные -Dallure.latest.* указатели на готовые снимки, без credentials. Указатели корня/API/UI переключаются согласованно под файловой блокировкой. Другие строки существующего maven.config сохраняются. Без поддержки атомарной операции публикация отклоняется, прежний указатель остаётся действительным. Не используйте одновременно два экземпляра IDE для одного рабочего дерева.

Стандартный plugin читает лишь рабочий input; его перезапись executor.json/allure.properties не меняет исходные результаты. Он может пересоздавать `view` текущего запуска и временный serve output, но не затрагивает канонический `html`, исходные JSON и старые запуски. Открытие не создаёт новые снимки/архивы; повторная публикация того же Run ID идемпотентна. Не переопределяйте вручную plugin output на исходный или канонический каталог.

`.pending-*` после действительно прерванной/ошибочной генерации сохраняется для диагностики, в указатели не попадает; автоматическое удаление не выполняется.

## History/Trend

API, UI и combined имеют разные цепочки. Сопоставление идёт по suite и инвентарю test/variant IDs. Publisher использует настоящий Allure 2.46.1: seed history берётся только из канонического HTML предыдущего сопоставимого запуска. Если прошлый завершённый запуск ещё никто не открывал, его канонический отчёт подготавливается однократно. Это сохраняет историю независимо от того, нажималась ли кнопка после каждого прогона.

Текущий запуск не включается в собственный seed history: повторные report/serve не добавляют его второй раз в Trend. Старые Allure history и отчёты других способов генерации сохранены. Все raw results и канонические отчёты находятся вне target. Allure может ограничивать число отображаемых точек; каталоги на диске не удаляются.

Сейчас API/UI Trend включает по два сопоставимых реальных запуска, combined — один полный запуск на 117 проверок. Синтетические прогоны с двумя проверками в эту историю не включены.

## Локальный runtime и безопасность

В проектный `.allure/allure-2.46.1` однократно скопирован уже установленный локально Allure Scoop 2.46.1. Сеть для подготовки и проверок не использовалась. На другой машине потребуется локальный Allure 2.46.1: проектный cache, Scoop или ALLURE_HOME. Publisher не скачивает программы. При недоступном runtime/ошибке генерации предыдущие указатели сохраняются; завершившиеся тесты не переопределяются ошибкой отчётности.

POM наследует стандартный io.qameta.allure:allure-maven:2.15.2 в модули. outputFormat=xdoc отключает только ненужную Maven Site skin-обёртку: сам Allure создаёт полноценный HTML. Это устраняет запрос Maven Site skin в offline-режиме.

.mvn/maven.config и .allure игнорируются Git; указатели содержат лишь локальные пути, Run ID и порядок запусков. Raw results не редактируются; текстовые данные дополнительно проверяются на известные секреты перед копированием. Для screenshots сохраняется ранее реализованное маскирование.

## Автономные проверки

- Offline Java 17 test-compile -DskipTests: BUILD SUCCESS обоих модулей.
- Настоящие стандартные allure:report без параметров путей: root — 117, API — 51, UI — 66; BUILD SUCCESS.
- allure:serve корня и модулей: проверены standard Maven goals и правильные аргументы input на заглушке CLI. Настоящий сервер и браузер не запускались согласно ограничению; отображение окна браузера остаётся ручной проверкой.
- LatestPublicationProbe на изолированных JSON fixtures: Passed/Failed/Broken/Skipped/Unknown, history двух запусков, шаги/вложения, идемпотентность, незавершённый/UI-only запуск, несовпадение Run ID и сохранность атомарного указателя — PASS.
- Полные API/UI-тесты, TestNG fixtures, браузер, HTTP и БД не запускались. clean/commit/push не выполнялись.

Новые исходники механизма: LatestAllurePublisher.java, LatestPublicationProbe.java; расширен ReportingListener; изменены три POM и .gitignore. Подробности сохранённой исходной архитектуры остаются в allure-reporting.md; ручные PowerShell-команды доступны как дополнительный путь для выбора старых запусков.

Финальная проверка сохранности: хеши **2183 исходных файлов результатов/вложений** не изменились. После стандартных Maven goals также неизменны **28 JSON файлов канонических метаданных и history/seed history**. В объединённом каноническом HTML проверены 117 test cases, 1383 шага и 503 файла вложений. Повторная генерация сохранила длину Trend: combined 1, API 2, UI 2 — без повторного добавления текущего запуска.

Рабочий `view` стандартного Maven Plugin — пересоздаваемый cache, а не архив. Отчётные цели могут обновлять его на месте; исходники, канонический `html` и старые запуски сохраняются. При запуске report у родительского проекта стандартный Maven reactor может также обновить рабочие view модулей — это те же фиксированные каталоги, без дополнительных архивов.
